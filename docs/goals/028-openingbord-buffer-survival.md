# 目標 028：`OPENBORD.PIK` 來源緩衝區存續驗證

狀態：completed（只確認取樣資料流；Issue #8 保持進行中）<br>
日期：2026-09-21<br>
對應 Issue：[ #8 ](https://github.com/wicanr2/colonization_cht/issues/8)<br>
前置證據：[目標 027](027-opening-pik-canvas-geometry.md)

## 目的

目標 027 已否定 `OPENING.PIK` 的畫布歸屬，並發現 `OPENBORD.PIK` 在同一 `5755` 緩衝區的完整讀取早於
畫布寫入。本輪只驗證該 `OPENBORD.PIK` payload 在 DOS 讀取完成後、`0AC2:04F4` 的 `MOVSB` 取用前及取用
窗口內，是否遭任何後續記憶體寫入覆寫。此為建立特定靜態候選的最小資料流前提；不解碼資產、不看圖、不判讀文字，
也不建立中文覆蓋。

## 執行項目

1. 從固定第 4,099,000 指令 state 與已確認 BIOS Enter 路徑重播，監看線性 `[57550h,59D55h)`；將
   `OPENBORD.PIK` 的 10,245 位元組 DOS 讀取與每一筆後續寫入按步數、位址、原始 `CS:IP` 分開記錄。
2. 同一窗口以記憶體讀取監看記錄對該範圍的讀取端；確認 `0AC2:04F4` 的 `MOVSB` 是否實際讀取仍存續的
   `OPENBORD.PIK` 範圍，並與目標 027 的 `ES=1C43` 畫布寫入收據交叉核對。
3. 若來源在取用前未被改寫，僅將可回查的「`OPENBORD.PIK` 原始緩衝區→取樣畫布寫入」列為 confirmed；
   若有覆寫或讀取端無法閉合，維持 unknown／強推論並記錄最小缺口。
4. 記錄輸入雜湊、state、dosgolem commit、位址空間、命令、收據雜湊與推論等級，回填現況、工作清單、
   Issue #8、工作歷程與 Git。所有原版衍生資料只留在 `workplace/reports/`。

## 結果

從第 4,099,000 指令 state 至第 4,157,000 指令，`OPENBORD.PIK` 的完整 payload 在第 4,103,486 指令讀至
`5755:0000`，範圍 `[57550h,59D55h)`。寫入監看其後沒有觀測到改變該範圍內容的寫入；此監看只報內容變更，
故不能排除值完全相同的寫入，但可確認 payload 沒有再被觀測為改變。

讀取監看記錄了 673 次 `0AC2:04F5` 的來源讀取（`0AC2:04F4` 是 `MOVSB`），時間為第
4,104,159–4,156,836 指令，讀取範圍 `[57556h,58129h)`；它完整包含在 `OPENBORD.PIK` 未改變的 payload
範圍。目標 027 的同一窗口另有 672 次同一 `MOVSB` 執行後的畫布內容變更。這證實 `OPENBORD.PIK`
原始緩衝區至少有取樣資料經 `MOVSB` 到達畫布；第 673 次目的端未改變，故未列入畫布變更計數。

這不代表整個 320×24 窗口、任何最終 VRAM 像素、圖像內容、文字存在或中文安全矩形歸屬於
`OPENBORD.PIK`。這些仍須在後續以獨立來源與畫面存續證據確認。

- 不因 `OPENBORD.PIK` 載入順序、共享畫布窗口、320×24 變更或檔名而假定它是最終像素矩形、靜態文字或覆蓋目標。
- 不用 `poke`、direct-entry、原版資料轉檔、人工圖像判讀或 OCR 製造資料流；不修改原版、dosgolem、遊戲行為或
  中文覆蓋。
- 不將 read watch、DOS 讀取、畫布寫入與較後 VRAM copy 的不同位址空間混寫；每個結論保留原始定位與工具名稱。
- 未達文字存在與中文安全矩形證據前，不建立 DRAFT／READY 規格、覆蓋原型或可發布資產。
