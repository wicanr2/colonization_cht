# 目標 024：首畫面正常輸入與動態輸出前沿

狀態：completed<br>
日期：2026-09-21<br>
對應 Issue：[ #5 ](https://github.com/wicanr2/colonization_cht/issues/5)<br>
前置證據：[目標 023](023-first-frame-draw-provenance.md)

## 目的

從已確認的第 2,000,000 指令 state v3，以一次標準鍵盤或滑鼠動作重播首畫面後的正常玩家輸入前沿，
確認程式實際消費的輸入服務，以及該動作是否引起下一個可觀測的畫面／文字輸出事件。這輪的目標是縮小
動態文字追溯的觀測範圍，不是猜測按鈕語意、跳轉流程或建立中文覆蓋。

## 執行項目

1. 先讀取 `cmd/probe` 的鍵盤與滑鼠注入參數及記錄格式；只使用可追溯的一次標準輸入事件，不以
   `poke`、direct-entry、批次按鍵或座標掃描替代正常玩家路徑。
2. 以同一個第 2,000,000 指令 state v3 為每次獨立重播的起點，在首幀已完成後分別送入一個標準
   鍵盤確認鍵與一個固定位置的單次滑鼠左鍵；逐項記錄輸入注入時間、原始輸入服務、消費／未消費結果、
   畫面模式與 VRAM 變化。
3. 在有狀態改變的輸入分支，觀測文字輸出 hook、B8000h、主控台輸出、檔案開啟與下一個 VRAM 寫入的
   原始定位；未命中時，只對該固定輸入與指令窗口記為 confirmed 未觀測。
4. 將可重播命令、固定輸入、檔案雜湊、dosgolem commit、位址空間與推論等級追加到研究紀錄；回填
   `CONTEXT.md`、工作清單、Issue #5、工作歷程與 Git。除非真正取得輸出鍵的充分證據，否則不建立
   DRAFT／READY 規格且不實作覆蓋。

## 停止線

- 不把未知首畫面的視覺內容、按鈕位置或鍵位語意當成已證實；輸入實驗只說明該一筆事件的結果。
- 不以 DOSBox／DOSBox-X 截圖取代 dosgolem 收據，不修改原版、原版資料、dosgolem 或遊戲行為。
- 不提交原版畫面、像素、存檔、解包物或其他原版衍生內容；中間收據只留在 `workplace/`。
- 若 probe 無法提供可追溯的單次正常輸入，記錄最小缺口並停止，不自行補造輸入機制。

## 退出條件

- [x] 已確認可用的單次鍵盤與滑鼠注入契約，且每次重播從同一 state v3 起點開始。
- [x] 每一個實驗均有輸入時間、觀測窗口、原始服務與畫面／文字結果的可重播收據。
- [x] 新的輸出分支保留原始定位、雜湊與推論等級；沒有取得文本鍵，也沒有誤稱已完成動態文字追溯。
- [x] 文件、Issue #5、Git、Docker 清理與原版素材權利邊界一致。
