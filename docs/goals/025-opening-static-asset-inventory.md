# 目標 025：開場靜態圖像候選的可追溯清冊

狀態：completed<br>
日期：2026-09-21<br>
對應 Issue：[ #8 ](https://github.com/wicanr2/colonization_cht/issues/8)<br>
前置證據：[目標 024](024-first-screen-normal-input-observation.md)／[Issue #5](https://github.com/wicanr2/colonization_cht/issues/5)

## 目的

依據已確認的正常輸入後開場資產序列，建立 `OPENING.PIK`、`OPENBORD.PIK` 與 14 個 `OPEN*.SS` 的固定雜湊、
檔案讀取、格式表面與畫面繪製候選清冊。這輪只要回答「哪些特定原版靜態圖像可以安全成為後續調查對象」，
不由檔名、像素或人眼猜測它們是否含文字，更不建立中文覆蓋原型。

## 執行項目

1. 從固定 `OPENING.EXE` 雜湊與目標 022 state v3，重播目標 024 已證實的單次正常輸入；以 DOS 檔案服務的
   開啟／讀取紀錄建立實際載入順序，而不是掃描目錄後假定所有檔案都會顯示。
2. 對實際載入的每一個資產記錄原始相對路徑、檔案大小、SHA-256、檔案服務時間、讀取 offset／長度，與已知
   的 mode 13h／VRAM 畫面觀測窗口；中間清冊只留在 `workplace/reports/`。
3. 在不匯出或提交原版像素的前提下，檢查已讀取資料的格式表面、來源緩衝區與可觀測繪圖端，將「已確認的
   靜態圖像候選」與「未知是否含文字」分開分級。格式不明時只記錄最小缺口，不假造 decoder。
4. 將可重播命令、固定輸入、雜湊、dosgolem commit、原始定位與推論等級追加至研究紀錄；回填現況、工作清單、
   Issue #8、工作歷程與 Git。除非候選本身的文字與幾何已有充分證據，否則不建立靜態覆蓋 DRAFT／READY 規格。

## 停止線

- 不把 `OPEN*.SS`、`*.PIK` 的名稱、檔案大小或單次載入順序當作內容、語意或文字存在的證據。
- 不將原版解包內容、點陣、截圖、調色盤、存檔或可重建素材的轉存檔納入 Git、GitHub 或文件。
- 不修改原版、遊戲行為、dosgolem 或中文覆蓋；不以 DOSBox／DOSBox-X 產物替換 dosgolem 收據。
- 不做 OCR、人工翻譯或字型／版面選擇；這些工作須待靜態候選與使用者原型決策後另行開啟。

- [x] 每筆候選都明列可觀測繪製關聯、證據等級與「是否含文字」的 unknown／confirmed 邊界。
- [x] 未將靜態資產載入或像素存在誤稱為可中文化文字，也沒有建立 DRAFT／READY 規格或覆蓋程式。
