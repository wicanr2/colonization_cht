# 目標 035：正式啟動鏈與開場離開碼 `0x6C` 消費者

狀態：completed<br>
日期：2026-09-21<br>
對應 Issue：[Issue #5](https://github.com/wicanr2/colonization_cht/issues/5)<br>
前置證據：[目標 034](034-opening-post-composite-enter-probe.md)

## 目的

目標 034 已在固定開場 composite 畫面證實：一個 BIOS Enter 會使 `OPENING.EXE` 以 DOS
`AH=4Ch, AL=6Ch` 結束。這只證實開場子程式的離開，不能推論它會啟動遊戲、`0x6C` 的語意，
或任何動態文字路徑。本輪依使用者選定的 B，改由使用者提供的 DOS 安裝目錄之正式啟動鏈，尋找
父程序／啟動器是否消費該離開碼，或誠實定位 dosgolem 尚缺少的最小服務。

## 執行項目

1. 在唯讀的 DOS 安裝目錄盤點可能的最上層啟動器與批次入口，只登錄可回查的檔名、雜湊、檔案類型及
   啟動鏈關係；不複製、提交或公開原始程式、批次內容或資料檔。
2. 以 dosgolem 從經證實的正式入口重播至它啟動／承接 `OPENING.EXE` 的邊界；記錄 EXEC、父／子 PSP、
   `AH=4Ch`、回傳碼與第一個消費者的原始定位、步數及檔案雜湊。原始輸入維持唯讀，且不以直接 state
   注入取代啟動鏈。
3. 若完整正式入口尚不能到達該邊界，縮小為一個可重現的 dosgolem CPU、DOS、視訊、音訊或輸入缺口；
   不將逾時、畫面停留或未觀測結果解讀為遊戲語意。
4. 僅在找到可觀測的文字輸出事件時，建立下一個窄的 RE 目標；不得因此建立動態文字 DRAFT／READY、
   譯文、字型、覆蓋程式或原版衍生版控內容。

## 結果

- 安裝目錄根層只有兩個批次入口候選：`COLONIZE.BAT`（50 bytes，SHA-256
  `4ea071484153da2716f77446fc6c7545645493fd369daf62fba8f395fa0bd9db`）與 `COLDEMO.BAT`
  （52 bytes，SHA-256 `ccc44d5c31aef794eea0b27f240970e31839923c10e487c4b1923f80ce7da97d`）。兩者都是
  CRLF 的 ASCII DOS batch 檔；私有、未保存原文的命令詞盤點確認各有兩個非空行：第一行是回音控制，
  最後一行的命令詞是 `opening`。因此兩者都沒有在該呼叫後留下批次分派／`ERRORLEVEL` 消費行。
- 依檔名將 `COLONIZE.BAT` 視為一般啟動**候選**只是強推論；其固定內容只證實它直接呼叫開場，不能證實
  `0x6C` 的名稱或其他 DOS shell 行為。`COLDEMO.BAT` 亦以相同的最終命令詞啟動開場，不能成為另一個
  已證實的離開碼消費者。
- dosgolem 固定副本（commit `1435f175e785ea096a9268cd1021a4222300bd43`）的 `cmd/probe -exe` 文件只列
  MZ／COM 輸入。最小重現將 `COLONIZE.BAT` 唯讀傳入並限為 1 道指令：它從 `0100:0100` 開始、停在
  `0100:0101` 且 `AX=0001`，沒有 EXEC、檔案、主控台或未實作服務。這是將批次位元組當作 COM 式程式碼的
  confirmed 行為，不是 batch 直譯；report SHA-256 為
  `373d74d8458f002241b69b62d47133210368efb722638b3f51520d9bd26921b6`，只留在 gitignore 的
  `workplace/reports/`。
- 故本輪沒有找到 `OPENING.EXE` 的 `0x6C` 父程序消費者；更精確地說，這兩份批次檔沒有其後的
  source-level 消費行，而 dosgolem 尚不支援以 batch／`COMMAND.COM` 正式重播這個啟動邊。DOS shell
  對回傳碼的更細語意、`OPENING.EXE` 的其他互動分支和動態文字輸出均維持未知。

## 停止線

- `OPENING.EXE` 的直接執行與第 034 輪 state 只可作交叉比對，不能冒充正式父程序路徑。
- 只追 `0x6C` 的 return／消費邊與達成下一個正常玩家可見狀態的必要鏈路；不反組譯與此無關的
  遊戲規則或把結束碼名稱猜成按鈕／場景語意。
- 即使抵達新畫面，也不以畫面外觀、資產名稱、A000 殘留或 B8000 空值直接升格為動態文字來源或
  中文安全矩形。

- [x] `OPENING.EXE` 的 `0x6C` 有已證實的父程序消費者與下一狀態，或有精確、最小且可重現的工具缺口；
