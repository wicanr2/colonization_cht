# 目標096：姓名固定提示的完整來源與正式覆蓋守門

狀態：completed；日期：2026-09-24。承接[目標095](095-player-name-input-and-overlay-gate.md)、
[規格023](../spec/023-player-name-screen-draft.md)，對應
[Issue #29](https://github.com/wicanr2/colonization_cht/issues/29)及
[Issue #26](https://github.com/wicanr2/colonization_cht/issues/26)。

## 玩家問題與本輪範圍

姓名畫面的原版提示有可追溯譯文、多色可逆背景與已量測的
38px 中文字模，但目前仍顯示英文。逐字印字暫存位置
`0x2A864` 不是完整訊息來源；若只憑首字或最終畫面套用
中文，可能誤蓋其他訊息或擦掉可編輯姓名欄。本輪要先
閉合「完整原文 → 當次印字 → 安全區 → 離頁失效」的
執行期證據，再依規格閘門嘗試正式中文覆蓋。

## 工作與退出條件

1. 先推送本目標至已確認 PRIVATE 的儲存庫；核對固定 DOS
   原版、隔離 `workplace/dosgolem` 與真視窗輸入收據。
   分析、建置、執行與抓圖只在有界 Docker；原版唯讀，
   原版畫面與字型只留已忽略的 `workplace/`。
2. 以 dosgolem 正常玩家輸入重播，在較早的
   `0E2D:09F4`／線性 RAM `0x2B072` 觀測完整來源；
   追至 `0D21:00C6` 對 `0x2A864` 的逐字讀取、
   `0D21:012C` 的415點畫布寫入。雙次冷啟動及無
   觀測控制比較 CPU、完整 RAM、索引、色盤、時間與
   開檔；另外量測原文重繪、姓名 `x`／退格、Enter
   離頁與游標遮擋，確定何時必須撤除補片。
3. 回填規格023：固定檔案雜湊、原始位址空間、完整
   訊息鍵、當次多色底圖、安全矩形、38px 字模與
   四邊內距、單行溢出／缺字回退、失效狀態及負例。
   只有證據足夠才升限定 READY；否則保留 DRAFT，
   留下可重播的最小缺口，不從可丟棄預覽搬正式程式。
4. 若已 READY，從唯一真 TSV 與固定字型重烘字模，
   在既有 Ebitengine／dosgolem 輸出層只覆蓋固定提示；
   姓名欄、原版 RAM、遊戲資料、規則與存檔完全不改。
   真視窗驗無輸入、字元、退格、Enter、游標、缺鍵／
   重複鍵、缺字／錯字級與錯版拒絕；與同輸入英文控制
   對比完整原版狀態。只有全部通過才標限定 CONFORMED
   並把正式中文段數由十四增為十五。
5. 將證據等級、驗收及未解範圍回填 `CONTEXT.md`、
   `RESEARCH-LOG.md`、`WORKLOG.md`、唯一工作清單與
   Issue #29／#26；推送私有 repo。收尾檢查原版素材
   未被追蹤、輸出 UID/GID、誤建目錄及 Docker 容器清理。

## 停止線

不把 `0x2A864` 的單字節當成整則來源，也不把離線
三情境原型當成正式玩家版。若完整來源與當次畫布事件
不能可靠配對，規格023保持 DRAFT，顯示原文，正式
中文數仍十四段；下一輪改追最窄的未證讀寫／轉場邊。

## 完成結果

目標已先以提交 `a34aa03` 推送私有儲存庫，才執行本輪研究。
dosgolem 雙次冷啟動與無觀測控制閉合完整來源、逐字輸出、
415點多色畫布及 Enter 離頁失效；`0E2D:09F4` 讀取使用
`DS:SI`，`0D21:00C6` 讀取使用 `SS:BX`，已在
[規格023](../spec/023-player-name-screen-draft.md)明確區分。
規格先升限定 READY，再接正式 Ebitengine 輸出層；
真視窗姓名 `x`／退格／Enter、中英文同輸入原版同狀態、
安全區及六類反例均由獨立驗證器通過，規格升限定 CONFORMED。
正式中文畫面文字由十四增至十五段；可編輯姓名與下一頁長文
保持原樣。本輪不新增含原版畫素的公開截圖，不宣稱完整中文化。
驗證收據、雜湊與未解邊界見規格023及[研究紀錄](../../RESEARCH-LOG.md)。
