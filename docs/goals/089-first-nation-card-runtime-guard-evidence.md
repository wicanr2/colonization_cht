## 玩家問題與邊界

第一張旗卡上、下兩處紅字已有來源固定的可逆中文原型，但仍不知道
實際執行時游標遮到哪一欄、滑鼠按鍵或換旗／切場後畫布與顯示層如何變化。
本輪只蒐集這些原版動態條件，供規格021的 READY 審查；不因原型 A／B
字級尚待使用者確認而停下可獨立查證的事實，也不自行定版。

## 執行與退出條件

1. 先推送本目標；固定合法 DOS 檔案 SHA-256、隔離 dosgolem、已驗
   16筆正常玩家輸入與第一張旗卡精確印字前後收據。原版與字型唯讀，
   探針、測試與畫面僅在限資源 Docker 容器，輸出只在 `workplace/`。
2. 以正常玩家輸入走到第一張旗卡後，對「游標不遮欄位、只遮上欄、
   只遮下欄、按下／放開」建立可重播的原版畫布、索引畫面、色盤、
   CPU／RAM／虛擬時間與滑鼠狀態收據。每一條件須有雙次重播及
   無觀測控制，不能以圖片觀感代替原版狀態。
3. 若正常滑鼠輸入可切換旗卡或離開此頁，追蹤下一個可達狀態與
   上、下紅字原版輸出是否仍匹配；若到不了，明確記錄輸入與能力
   邊界，不猜測其他旗卡內容。
4. 建立獨立驗證器，檢查每條件的游標遮擋、底層可逆背景及逐欄
   回退所需不變量；將證據與未知更新至規格021、研究紀錄、
   `CONTEXT.md`、工作清單及唯一 `WORKLOG.md`。推送私有 repo，
   回填 Issue #12／#26；驗證原版素材不入 Git、檔案擁有權及
   Docker 容器清理。

## 停止線

不升 READY／CONFORMED，不更新正式截圖，也不增加十四段正式中文數。
如原版沒有重繪或切換旗卡的當次證據，只保留已量到的範圍，不用

## 限定結果

`tools/probe_goal089_nation_runtime.go` 在隔離 dosgolem 從已驗16筆
真視窗輸入冷啟動至43M步，再分三條正常滑鼠路徑運行至46M步：
上欄→下欄→移開、第一張旗卡下欄左鍵按下／放開、相鄰右上旗卡
中央左鍵按下／放開。三條路徑各做兩次獨立重播及無逐幀觀測
控制組；同條路徑的兩次 JSON 逐位元組一致，控制組的 CPU、完整
RAM、原版索引畫面、色盤、虛擬時間、開檔序列及每個檢查點畫布
皆與觀測組一致。

- 游標在 `(156,18)` 時只改變上欄安全區24個索引像素；在
  `(156,90)` 時只改變下欄24個；移開到 `(16,16)` 後兩欄與原版
  基準相同。整條路徑的底層畫布保持目標088原文畫布，故是游標
  合成遮擋，不是重新印字。
- 在第一張旗卡下欄 `(156,90)` 按住左鍵（dosgolem button 0，
  原版按鈕狀態1）及放開後至46M步，兩欄底層畫布仍未改變；
  這只證明該座標與時間窗，不能外推所有按鍵或遊戲選國語意。
- 在相鄰右上旗卡 `(255,50)` 按左鍵後，首個觀測幀仍保留舊卡；
  下一幀的原版底層畫布重繪，舊上／下安全區分別與基準相異
