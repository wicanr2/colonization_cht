# 目標164：GUI 驗證腳本改為步數對齊（Issue #40）

狀態：完成；2026-09-27～28。對應 [Issue #40](https://github.com/wicanr2/colonization_cht/issues/40)。

## 問題

真 GUI 腳本以牆鐘 `sleep .2` 分隔滑鼠移動、按下與放開。前端每次 Update 先讀一次輸入、再執行 200,000 步；主機高負載時一次 Update 可能超過 0.2 秒，按下與放開落在同兩次讀取之間就整個遺失，移動與按下也可能在同一畫格送達（目標134、136、161 的失敗例）。

## 範圍

- 新增共用函式 `tools/gui_step_input.sh`：每個 xdotool 動作後等狀態檔步數至少前進兩次 Update，確保動作已被讀到；按下至少維持兩個畫格。
- 全部 18 支真 GUI 腳本改用共用函式，移除各自的牆鐘版本。
- 既有收據不重跑；重播只依收據內的步數，不受腳本改動影響。

## 退出條件

- 高負載下法國、西班牙、荷蘭選國各跑兩次，介紹頁事件都是該國（沿用目標137 檢查器的國別斷言）。
- 輸入收據中每個按下都不與移動同步數、放開與按下相距至少兩次 Update。

## 結果

- 牆鐘版收據的統計證實時序問題：目標161 的真 GUI 收據裡，多數點擊只按住一次 Update（20 萬步），也常與移動落在同一步數。新檢查器 `tools/check_goal164_step_clicks.py` 會擋下這種收據（反向對照 `neg-wallclock` FAIL）。
- 選國失敗的真正成因不只是按住太短：腳本在 43.5M 步有一下 `click 220 200`，原本是給更早的畫面用的。高負載下畫面出現時機漂移，這一下落在選國頁左側，原版把它當成「完成」，以預設的英國進入姓名頁。舊收據能選到法國，是因為按下後游標在放開前已移到法國旗卡。
- 修正：
  - 共用函式 `tools/gui_step_input.sh`：每個動作等前端讀到才繼續，按下至少維持兩個畫格；`wait_screen` 等畫面階段出現再前進。
  - 前端狀態檔新增 `nations` 階段（開啟 `NATIONS.PIK`）。
  - 兩支選國腳本改為等選國頁畫完再點旗卡，刪除多餘的 `click 220 200`。
  - 18 支真 GUI 腳本全部改用共用函式。
- 驗收：主機負載 68～127 下，法國、西班牙、荷蘭各跑兩次，介紹頁事件都是該國，按下與移動不同步數、按住都至少兩次 Update，後段的 Left 鍵與遊戲選項開窗也正確。檢查器 PASS。

收據只在忽略的 `workplace/reports/goal164-step-clicks/`；第一次嘗試（仍保留 `click 220 200`）封存在 `attempts/wallclock-card-race/`。
