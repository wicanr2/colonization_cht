# 目標093：姓名畫面來源與正常玩家輸入

狀態：進行中；日期：2026-09-24。承接[目標092](092-neighbor-card-runtime-and-nation-route.md)、
[規格023](../spec/023-player-name-screen-draft.md)，對應
[Issue #29](https://github.com/wicanr2/colonization_cht/issues/29)。

## 玩家問題與範圍

原版已能從正常滑鼠路徑抵達姓名畫面，但「Please Enter Your Name.」及
「Jacques Cartier_」的來源、動態或靜態分類，以及姓名按鍵與確認行為均未知。
本輪以固定原版、隔離 dosgolem 和既有十六筆輸入收據重播，先解出這些
玩家可見事實，不修改原版資料、遊戲規則或存檔。

## 執行與退出條件

1. 先把本目標推送至已核對為 PRIVATE 的儲存庫。確認原版檔案 SHA-256、
   dosgolem 副本提交、輸入 JSON 與既有姓名畫面控制組；所有分析、建置、
   探針、測試與抓圖只在限資源 Docker，原版唯讀，輸出只留 `workplace/`。
2. 搜尋候選原始位元組後，以 DOS 讀取、RAM、輸出呼叫與畫布事件分別追查
   提示及預設名稱；若某欄為圖像烘入，需有資產與畫面定位證據。
   每筆結論註明檔名、雜湊、位址空間、工具版本、推論等級及反例。
3. 從姓名畫面以正常鍵盤事件測試至少「保持不輸入」、一個可見字元、
   退格及 Enter；比較畫面、CPU、完整 RAM、檔案開啟、虛擬時間及下一
   玩家狀態。至少兩次冷啟動與無逐幀觀測控制；不得用記憶體注入或
   direct-entry 替代正常玩家路徑。
4. 把新證據回填規格023、研究紀錄及 `CONTEXT.md`。只有來源、輸出事件、
   字級／安全矩形、回退與輸入隔離均證實，且 READY 審查通過，才可接
   正式中文顯示及真 Ebitengine 同狀態驗收；否則保持 DRAFT、原文顯示
   與十四段已驗正式中文數量不變。
5. 完成後更新 `WORKLOG.md`、唯一工作清單與 Issue #29，推送私有 repo；
   核對原版素材未被追蹤、檔案 UID/GID、誤建目錄及 Docker 容器清理。

## 停止線

使用者姓名屬原版輸入狀態；不因畫面翻譯而變更姓名位元組、查找或存檔。
不能把視覺文字猜作穩定鍵，也不能把一個可見畫面當成完整玩家流程驗收。
若輸入測試進入新畫面，只建立可回查的下一步 DRAFT，不未經證據直接覆蓋。
