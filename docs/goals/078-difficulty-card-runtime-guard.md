## 問題與範圍

第一張卡片兩行的原始 TXT → 執行期字串 → 字形 → 像素鏈已閉合；
離線 Ebitengine 預覽也能恢復有紋理底圖。但固定終點的預先存檔畫布，
不能證明正常執行中每次重畫都可取回原始底圖，也未驗證滑鼠遮擋與後續繪圖。
本輪只在隔離 dosgolem 的真實正常玩家路徑，建立可重播的執行期擷取與回退實驗；
不預先把 DRAFT 原型接入正式 `live_menu.go`。

## 工作與退出條件

1. 固定原版檔案雜湊、九筆真視窗輸入及 dosgolem 版本，於兩行原文真實讀取
   與字形畫布寫入附近收集執行期前後畫布、索引畫面、色盤、游標座標／按鍵及
   20-bit RAM／真實模式 `CS:IP`。觀測者不得改原版記憶體或玩家輸入。
2. 以遊戲專屬、可丟棄的守門探針從當次原文繪製前畫布建立兩欄有紋理背景補片，
   對每個候選顯示幀核對完整原文、字形差分、半開安全矩形、背景與游標／後續繪圖。
   橫跨不同時刻的舊補片、遮擋、缺譯／缺字模須回退原文並記錄原因；原版檔案
   指紋不符則在啟動前拒絕套用中文，不拿未知版本冒充原文畫面驗收；
   不得改原版畫布來讓測試通過。
3. 至少以兩次獨立正常玩家重播及一組卡片游標進出或同等反向條件驗證：
   原版 CPU／RAM／索引畫面／色盤不因觀測與輸出合成改變；合成差異只在兩欄
   安全矩形。若游標由原版畫在畫布之外，須明確記錄能力邊界，不能假稱已測遮擋。
4. 依實測更新規格016的 confirmed／unknown、可重跑工具與本機收據；
   只有 READY 審查能授權正式覆蓋。更新 `CONTEXT.md`、`RESEARCH-LOG.md`、
   `WORKLOG.md`、私有 GitHub 儲存庫與對應 Issue，保留 Docker 清理與權利邊界。

## 停止線

不修改原版 DOS 檔案、存檔或規則，不修改 dosgolem 上游，也不把原版畫布快照、
原版素材、字型或含原版像素的 PNG 加入 Git。第一張卡片的結論不能外推其餘卡片；
本輪沒有足夠證據時維持規格016 DRAFT 與原文回退，已顯示中文數量不增加。

## 結果與退出判定

- confirmed：`tools/probe_card_runtime.go` 只觀測原版 `0E2D:11CF` 真實讀取，
  稱號／副標分別在步數29,797,568／29,813,172 擷取當次畫布；
  兩份繪製前安全矩形雜湊與目標075的原版快照一致。步數29,865,000 的
  第一個兩行完成輸出幀，以164／83點、既有 bbox 的原始差分建立可逆補片。
- confirmed：相同九筆真視窗輸入的兩次獨立觀測報告位元組一致，SHA-256
  `f8c8ebe95e09c4f8793f6dff2c72fedff9bd251e209ea887aedfb437e86c8fc6`。
  該幀及後續共13個輸出幀，逐幀核對完整原文與 NUL、視訊模式、已開啟檔案
  脈絡及索引畫面後，兩欄均套用；無觀測控制組的 CPU、完整 RAM、索引畫面、色盤、
  ticks／cycles 與觀測組一致，也符合目標077既有正常路徑終點。
- confirmed：在原版卡片完成後將滑鼠移入 `(160,48)`，索引畫面相對基準
  改變160點，與兩欄安全矩形分別交疊7／60點；底層卡片畫布不變。
  不加保守游標守門的補片也會因兩欄原始像素不符而回報 `frame-mismatch`。
  保守守門在25個幀回退原文；移到 `(16,16)` 後24個幀重新套用。
  游標變體與其無觀測控制組同輸入原版狀態一致。
- 反向條件：模擬缺譯、缺字模時輸出逐像素等於原文控制圖；
  改動一點舊畫面則拒絕該欄補片。臨時唯讀連結將 `NAMES.TXT` 指向
  錯誤指紋的 `GAME.TXT`，探針在啟動前拒絕該版本，沒有猜測套用。
  執行期軟體合成圖經獨立逐像素檢查：稱號／副標安全區變更
  2,752／1,860點，兩欄外不變；中文字級仍依原版墨跡分別為21／25px候選。
- 完整五組原版報告及兩張含原版像素的 PNG 僅留已忽略的
  `workplace/reports/goal078-card-runtime-*`。檢查器 `tools/check_card_runtime.py`
  及重跑契約見[RESEARCH-LOG.md](../../RESEARCH-LOG.md)。這是固定第一張卡片的
  **可丟棄原型**，尚未接 `live_menu.go`／Ebitengine 正常玩家前端；
  格式化正式鍵、其餘卡片、實際缺譯來源與更廣玩家狀態仍待驗。
  規格016保持 DRAFT，已正式顯示中文仍八段。
