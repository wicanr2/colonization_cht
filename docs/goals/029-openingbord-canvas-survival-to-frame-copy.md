# 目標 029：`OPENBORD.PIK` 取樣畫布至 VRAM copy 的內容存續

狀態：completed（只確認資料流至一次 VRAM copy；Issue #8 保持進行中）<br>
日期：2026-09-21<br>
對應 Issue：[Issue #8](https://github.com/wicanr2/colonization_cht/issues/8)<br>
前置證據：[目標 028](028-openingbord-buffer-survival.md)

## 目的

目標 028 只閉合 `OPENBORD.PIK` 原始緩衝區到 `1C43` 共用畫布的 672 次內容變更。本輪只驗證這些畫布位置所在的
320×24 範圍 `[1C430h,1E230h)` 是否在其處理窗口結束後維持內容，直到已知 `0557:009F` 的
畫布→mode 13h VRAM 搬運實際讀取該範圍。這是資料流存續驗證，不解碼或判讀資產，不把範圍當成圖像／文字矩形，
也不建立中文覆蓋。

## 執行項目

1. 從目標 027 的第 4,156,900 指令 post-window state 重播至涵蓋已知後續 canvas→VRAM copy 的窄窗口；監看
   `[1C430h,1E230h)` 的內容變更，以判斷本輪可觀測範圍內是否遭改寫。不得以「沒有 change 事件」聲稱完全沒有寫入。
2. 對同一範圍啟用粒度 1 的讀取監看，將每筆讀取按步數、位址、原始 `CS:IP` 分組；以 raw 指令 bytes 與暫存器
   收據核對 `0557:009F`／其後 IP 的 `REP MOVSW` 是否以 `DS=1C43` 將資料讀入 `A000` VRAM 搬運。
3. 只有同時具備「未觀測內容改變」與「已確認 copy 讀取」時，才將特定、被目標 028 確認的畫布內容變更延續到
   VRAM copy 前列為 confirmed；若改寫或讀取端不閉合，依證據降為強推論／unknown，不補猜像素。
4. 記錄固定輸入、state、dosgolem commit、位址空間、監看上限與收據雜湊，並將推論等級回填研究紀錄、現況、
   工作清單、Issue #8、工作歷程與 Git。所有原版衍生內容仍只留在 `workplace/reports/`。

## 結果

從第 4,156,900 指令的 post-window state 跑至第 5,500,000 指令時，`[1C430h,1E230h)` 的內容變更監看
留下零筆；此 observer 只看內容變更，因此不排除值相同寫入。粒度 1 的讀取監看留下剛好 7,680 筆，完整覆蓋
`1C430h–1E22Fh`，沒有範圍外紀錄。

這 7,680 筆分成第 #5,464,375 至 #5,464,536 指令的 24 組，每組 320 bytes，觀測 IP 都是
`0557:00A1`。其前一個原始指令 `0557:009F` 的 bytes 為 `F3 A5`（`REP MOVSW`）；24 個前置暫存器樣本為
`DS=1C43`、`ES=A000`、`CX=00A0`，`SI`／`DI` 每列遞增 `0140h`。因此該完整 320×24 canvas 範圍在本輪可觀測
窗口內存續，並於這一次 copy 搬至 mode 13h VRAM。目標 028 已確認的 672 次 `OPENBORD.PIK` 取樣畫布內容變更
位於此完整範圍，故其內容也已 confirmed 地抵達這次 VRAM copy。

這不是 `OPENBORD.PIK` 的完整資產歸屬或穩定最終畫面。此輪未驗證 copy 後的 VRAM 是否再被改寫，也未判讀
圖像、文字存在或中文安全矩形；上述資料流不能授權 DRAFT／READY 規格、覆蓋原型或中文化實作。

## 停止線

- 不把「畫布內容存續」擴張為 `OPENBORD.PIK` 的完整資產歸屬、最後畫面矩形、圖像語意、文字存在或中文安全矩形。
- 不使用 `poke`、direct-entry、OCR、人工圖像判讀、資產解碼或原版素材輸出；不修改原版、dosgolem、遊戲行為或中文覆蓋。
- 不把 `-watch` 無內容變更誤述為沒有值相同寫入；不混淆 IDA 線性位址、執行期線性位址與 `segment:offset`。
- 未有文字存在和中文安全矩形的獨立證據前，不建立 DRAFT／READY 規格、覆蓋原型或可發布資產。
