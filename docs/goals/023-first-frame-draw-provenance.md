## 目的

從已確認的第 2,000,000 指令 state v3 追溯首個 mode 13h VRAM 寫入端 `0557:0090` 的暫存器、`SS:SP` 與來源
資料範圍，分類它是靜態圖像載入／繪製或文字輸出候選。同時明確記錄這個無輸入正常路徑在 20M 指令內沒有
觀測到的動態文字事件，避免將「畫面存在」誤寫成「已找到文本鍵」。

## 執行項目

1. 從固定 state v3 在 2.70M–2.75M 窗口重播，於 `0557:0090` 記錄寄存器、`SS:SP` 與原始 `CS:IP`，並保留
   檔案雜湊、工具版本與位址空間。
2. 以來源指標、當前資料段、相鄰檔案存取與 VRAM 寫入型態交叉判定首畫面 payload 的證據等級；不由檔名、
   像素數或人工觀感猜測其內容。
3. 只在固定的無輸入正常路徑確認動態文字 hook／B8000／主控台輸出是否命中；若未命中，將它列為此窗口的
   confirmed 未觀測，而非宣稱遊戲沒有動態文字。
4. 回填研究與現況、更新 Issue #5、工作清單、Git 與 Docker 清理；除非已足以定義訊息鍵，否則不建立
   DRAFT／READY 規格且不實作覆蓋。

- 不把首畫面中的可能標誌、靜態字樣或圖像語意當成已確認，且不提交原版衍生像素。
- 不修改 dosgolem、原版資料、遊戲行為或中文覆蓋；這輪只產生 RE 證據。
