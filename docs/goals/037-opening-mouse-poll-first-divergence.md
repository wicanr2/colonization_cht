# 目標 037：開場滑鼠輪詢的第一個控制流分歧

狀態：completed<br>
日期：2026-09-21<br>
對應 Issue：[Issue #5](https://github.com/wicanr2/colonization_cht/issues/5)<br>
前置證據：[目標 036](036-opening-composite-known-click-probe.md)

## 目的

目標 036 已確認完整開場畫面 state 中的中央左鍵會被 `int 33h AX=0003` 讀取並走向退出。要找其他正常
互動區，不能直接掃描座標。本輪只在首次輪詢前後的極短窗口，對照無輸入與既有中央左鍵，定位第一個實際的
`CS:IP`／暫存器分歧與它消費的輸入欄位；不替未證實的程式碼命名為 hit-test 或按鈕處理器。

## 執行項目

1. 從第 #5,465,772 指令 state 分別以無輸入與單一 `(160,100)` 左鍵重播到首次 `int 33h AX=0003`
   後的有界終點；兩組輸出原始 trace、服務統計與必要原始 bytes 到 gitignore 的 `workplace/reports/`。
2. 逐指令比較兩組 trace，記錄第一個不同 `CS:IP`、暫存器或條件結果；若需要 raw bytes，只擷取該固定
   `CS:IP` 的最小範圍並標明 dosgolem 的 real-mode segment:offset 位址空間。
3. 追到第一個按鍵／`CX`／`DX` 值被消費的指令或明確工具限制即停止。不得據此推論矩形邊界、其他控制項、
   按鈕名稱、文字語意或新的玩家路徑。
4. IDA Pro 9.4 映像只能在其技能指定的工具契約可回查時使用；目前該 README 與 `ida-94-tools.md` 未在
   指定位置找到，故本輪先保留為工具環境限制，不能將未驗證的 IDA 輸出升格為證據。

## 結果

- 兩條路徑從相同 state 各執行 427 道指令至 #5,466,200，並都只呼叫一次 `int 33h AX=0003`。
  初始 77 指令窗口確認該服務在 #5,465,840 回傳：控制組為 `BX=0, CX=0, DX=0`；左鍵組為
  `BX=1, CX=320, DX=100`。`CX=320` 與注入 X=160 相符於 mode 13h 的水平倍率，這是服務回傳值，不是
  遊戲的邏輯座標／矩形證據。
- 兩組的第一個 `CS:IP` 分歧在 trace record #95：控制組於 `0110:0954`、`AX=0000` 跳到
  `0110:0960`；左鍵組於相同位置、`AX=0001` 落入 `0110:0956`。從 `0110:094F` 擷取的 96 bytes
  （dosgolem real-mode segment:offset，SHA-256
  `0880c0b81d4745f3ec7c3f077e5a8248fe23669e6fed0210b77c31a1ebb6acf1`）中，`0952` 是 `0B C0`
  （`OR AX,AX`），`0954` 是 `74 0A`（`JZ 0960`）；左鍵分支接著在 `0956` 寫入常數 `001Bh` 至
  `[BP-0Ah]`，而非零分支與該常數的語意均未知。
- 所以本輪已證實的是一個「按下存在」的 boolean consumer；它不是座標 hit-test、按鈕名稱、矩形界線、
  動態文字或覆蓋資格。後續應在上游追溯 `AX` 如何由 `BX/CX/DX` 產生，且在找到可證實區域前不再注入座標。
- IDA Pro 9.4 映像存在，但技能要求的工具專案 README 與 `ida-94-tools.md` 不在指定位置；映像 entrypoint
  亦未暴露額外唯讀掛載。故本輪沒有使用未驗證 IDA 結果，所有結論只依 dosgolem trace／dump。
