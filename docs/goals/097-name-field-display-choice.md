# 目標097：可編輯預設姓名欄的顯示界線與對照原型

狀態：研究與可丟棄原型已驗；待使用者決定，未完成正式顯示；
日期：2026-09-24。承接[目標093](093-player-name-source-and-input.md)、
[目標096](096-player-name-prompt-runtime-guard.md)與
[規格023](../spec/023-player-name-screen-draft.md)，對應
[Issue #29](https://github.com/wicanr2/colonization_cht/issues/29)。

## 玩家問題與本輪範圍

固定提示已安全顯示中文，但原版預設姓名 `Jacques Cartier_` 是
可編輯的玩家資料，不是固定標籤。原始姓名仍須維持原版輸入、
查找、規則及存檔；尚未決定是否只在未編輯的畫面顯示譯名。
本輪只補齊原版姓名欄的畫素／編輯邊界，製作「保留原名」與
「僅未編輯時顯示譯名」的可丟棄同畫面對照，供使用者作取捨。
未獲確認前，不把譯名或新覆蓋鍵接入正式前端。

## 工作與退出條件

1. 先將本目標推送至已核對為 PRIVATE 的儲存庫；確認固定 DOS
   原版、隔離 `workplace/dosgolem`、已驗真視窗輸入與輸出目錄。
   原版唯讀，分析、建置、遊戲執行、抓圖與驗證只在限資源 Docker；
   含原版畫素的原型只留已忽略的 `workplace/`。
2. 以 dosgolem 正常玩家路徑重播原版姓名欄無輸入、`x`、退格、
   Enter；從固定 `NAMES.TXT` bytes、20-bit RAM、實模式輸出
   至320×200畫布量測預設姓名墨跡、游標、框線及每次重繪的
   安全區。雙次冷啟動並設無觀測控制，對比 CPU、完整 RAM、
   原版索引、色盤、時間與開檔，不以單張截圖當成原版契約。
3. 從已驗收的 Ebitengine 姓名畫面建立兩個**可丟棄**版式：
   A 保留原名，B 僅初始預設名的輸出畫布上顯示可追溯繁中
   譯名；對 B 量測 Cubic 11 欄位專屬字級、墨跡、安全矩形、
   游標位置與最長文字。`x`／退格／Enter 情境必須顯示原版
   玩家輸入，不可讓譯文參與原版記憶體或存檔。對照圖不得
   當成正式玩家版，也不替使用者定案字體或名稱譯法。
4. 以獨立驗證器確認原型只在候選欄位安全區改變畫素，
   原版狀態、可編輯姓名與下一頁均與同輸入英文控制一致；
   若證據不足則只留下最小可重播缺口，不做正式覆蓋。
5. 將證據等級、兩種方案的忠實度與操作影響回填研究紀錄，
   向使用者展示可比較的實際畫面並只問一個父層決策：
   姓名欄維持原名，或在未編輯預設值時僅於畫面顯示譯名。
   在回答前，[Issue #29](https://github.com/wicanr2/colonization_cht/issues/29)
   保持 OPEN；更新唯一工作清單、歷程及遠端 Issue，推送私有 repo。
   收尾檢查原版素材、UID/GID、誤建目錄與 Docker 容器。

## 停止線

不修改原版姓名 bytes、輸入語意、查找、遊戲規則或存檔；
不因一個預設名推廣到其他國家、人名或玩家自訂姓名。
視覺選項與譯名未經使用者確認前，不建立正式 READY 規格，
不增加十五段已驗中文顯示數，也不關閉 Issue #29。

## 本輪已驗結果與未完成界線

- 已按固定16筆正常玩家輸入，從冷啟動走至姓名畫面。原版 `NAMES.TXT`
  SHA-256 `4bf5ba261f71e9215450801d0ac4b00a66e91b046a3b592516524bea03bd6061`，
  檔案位移 `0xB4B` 的15 bytes 是 `Jacques Cartier`；畫面逐字讀取
  `0D21:00C6`／20-bit 線性 RAM `0x2A972`，畫布寫入位於
  `0D21:012C`。286筆改色寫入的 bbox 為原版320×200畫布
  `(82,101)–(164,110)`；淨變更285點。輸入框原版 bbox
  `(79,98)–(246,112)`，候選內部安全區 `(80,100)–(245,111)`。
  雙次冷啟動報告相同，無觀測控制在各取樣點的 CPU、完整 RAM、
  索引、底層畫布、色盤、時間與開檔相同。
- 正常路徑的 `x`、退格及 Enter 原版分支已核對；`x` 與退格的
  畫面差分只在姓名框，Enter 則抵達下一頁。這證明欄位可編輯，
  **不**證明將中文放上去後的輸入切換或存檔語意已驗收。
- 本機 A 圖是既有已驗真 Ebitengine 姓名畫面逐像素副本；B 圖只在
  姓名安全區顯示「中文譯名示意_」，A／B 差分四倍畫布 bbox
  `(328,404)–(656,440)`。B 採 Cubic 11 候選38px、實測
  268×35px、左上 `(328,404)`，只是可丟棄排版檢查，**不是**
  `Jacques Cartier` 的已查證譯名，也沒有接入正式前端。
  本機原型及驗證收據位於已忽略的 `workplace/reports/goal097-name-field/`；
  獨立驗證器 `tools/check_goal097_name_preview.py` 重跑 PASS，收據
  SHA-256 `0e6ece12a6452d56b4e473ebf1f5bcba5e5aa3006a3efc06634ee015332f185f`。
- 原定第3項的「可追溯繁中譯名」、B 方案輸入後恢復原名的正式
  顯示守門及逐欄回退**尚未完成**。先請使用者決定父層 A／B；
  若選 B，另查譯名、建立 READY 規格並完成真視窗中英文同狀態
  驗收。Issue #29 維持 OPEN，已驗正式中文仍為十五段。
