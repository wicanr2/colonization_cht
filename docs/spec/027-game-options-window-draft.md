## 現有原版證據與未知

目標110固定原版視窗在1,275M與1,300M的索引畫面 SHA-256 都是 `7093e83e87169f8eb15e733c3d69ec68afd5b78a5d304fa384819c987192a546`，色盤 SHA-256 `b81c99f3ef54dd7015107ece98b6770620b4c3472281172a92f0302f8ec6b4c9`。目標112的可丟棄探針開啟 `-options-audit`，在1,253,314,011步取得九段 `GAME.TXT` 同一512-byte DOS 讀取目的緩衝：標題線性 `0x2B0CF`，第1至8列線性 `0x2B0EB`、`0x2B0FF`、`0x2B114`、`0x2B127`、`0x2B135`、`0x2B140`、`0x2B152`、`0x2B168`。各段與固定原始 bytes 相符。原版 `0E2D:1F76` 隨後從線性 `0x2B0CF–0x2B176` 依序讀取168個 bytes，與 `GAME.TXT:0x4CD–0x574` **逐 byte 完全相同**；這一段包含標題、控制行、八列與換行。原版 `0D21:00C6` 在1,253,411,339～1,253,588,150步附近依序讀到不帶 `~` 的標題與八列可見字；但讀字常式的直接 RAM 位址是中間字元緩衝，不是上述檔案讀入目的位址。**目標112當時**尚未觀測到中間搬運；後續目標114／115已閉合印字緩衝的直接寫入，唯 DOS 解析緩衝至高位址 RAM 的逐 byte 中間邊仍未閉合，詳見下節。

兩次冷啟動收據逐位元組一致；無記憶體監看控制的 `route`、`sources`、`transfers`、全部 `samples`、開檔、鍵盤事件與輸入相同，1,300M 原版索引畫面也相同。[獨立檢查器](../../tools/check_goal112_options_source.py) PASS，[七項正反例](../../tools/test_goal112_options_source.py) PASS，含缺原版 `SKIP 77`、錯 DOS 來源、錯解析讀取、漏印字、壞原版畫面及無監看控制分歧。原版完整收據僅在已忽略的 `workplace/reports/goal112-options/`。

已證實：固定原始位移／bytes、DOS 目的緩衝、原版168-byte逐 byte 讀取、正常玩家開窗、九段印字常式輸出與穩定畫面墨跡；目標114／115另閉合當次印字緩衝的直接讀寫。強推論：DOS 解析緩衝經中間路徑產生同次高位址九段來源，尚未逐 byte 直接閉合。未知：反白列與核取圖示在各種操作下的完整每幀補片相位；適合每欄的中文字級、顏色與快捷鍵視覺呈現；`Tutorial Hints` 圖示是否代表啟用。

### 目標114／115追加：高位址來源與印字緩衝的直接邊

修正後探針以一個監看範圍同時覆蓋印字緩衝和畫布；另一互斥重播專門監看高位址 RAM。雙次冷啟動各自 JSON 逐 byte 相同，另有無監看控制；控制組的正常玩家路徑、原版狀態快照、索引畫面、色盤、開檔及輸入一致。原版20-bit **線性 RAM** 的九段高位址起點依序為 `0x743C0/0x743EC/0x7441A/0x74449/0x74476/0x7449E/0x744C3/0x744EF/0x7451F`（十進位476096／476140／476186／476233／476278／476318／476355／476399／476447）；九段原始正文共142個 byte 在 DOS 讀取之後，分別於原版實模式 `0E2D:11A5`（標題16個）及 `0E2D:11EB`（八列126個）觀測到同址、同值的變更寫入。這些是 RAM 地址及 `CS:IP`，不是 `GAME.TXT` 檔案位移。

標題16字與八列含核取前綴的134字，共150個可見非零字元；`0E2D:11A5` 對印字緩衝線性 `0x2AC78`／`0x2ADDE` 有157筆變更寫入。每個可見字元在 `0D21:00C6` 讀取前57步，均有同址、同值的寫入；寫入前7步，`0E2D:1194` 又從標題中繼 `0x2ACEA`／列中繼 `0x2AE50` 讀到同值。列格式常式 `8BDF:058E` 的134筆中繼變更寫入中，133筆可對上13步前 `8BDF:0567` 同值來源讀取；另1筆（步數1,253,468,919）的來源讀取未被此監看視窗捕捉，原因仍未知。標題局部18筆複製則有 `0E2D:11EB` 同一步、同值暫存區讀取。

這些逐字邊**已證實**；但 DOS 解析緩衝 `0x2B0CF–0x2B176` 至高位址 RAM 的中間路徑尚未逐 byte 直接閉合，一筆格式化來源也未捕捉，不得把整條 `GAME.TXT`→最終畫面宣稱完全閉合。`Machine.WatchWrites` 只通知值變更；142個來源 byte 各有至少一次變更寫入，不能由此推論相同值寫入不存在。[獨立檢查器](../../tools/check_goal114_options_dataflow.py)及[正反例](../../tools/test_goal114_options_dataflow.py)已核對雙重播、控制、錯來源／寫入／RAM、錯輸入、錯原版及缺原版 `SKIP 77`。原始收據只在已忽略的 `workplace/reports/goal114-options/`。

沿相同 `OPENING.EXE -g` 至海上介面的正常玩家路徑，1,300M 固定視窗索引 SHA-256 仍為 `7093e83e87169f8eb15e733c3d69ec68afd5b78a5d304fa384819c987192a546`。只移到第一列 `(140,65)`、只移到末列 `(140,149)`、移到框外 `(20,100)`，以及在框外按 ESC 是**原版 DOS 滑鼠／鍵盤事件**，座標屬320×200玩家畫布，不是四倍輸出座標。三分支各兩次獨立冷啟動 JSON 逐 byte 相同，另有無監看控制；每一分支的 CPU／完整 RAM／索引／色盤／時間、開檔和輸入消費與自己的無監看控制一致。固定事件 SHA、收據 SHA 與可重跑檢查見[目標116](../goals/116-game-options-selection-and-exit-phases.md)。
