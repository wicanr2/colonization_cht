## 現有原版證據與未知

目標110固定原版視窗在1,275M與1,300M的索引畫面 SHA-256 都是 `7093e83e87169f8eb15e733c3d69ec68afd5b78a5d304fa384819c987192a546`，色盤 SHA-256 `b81c99f3ef54dd7015107ece98b6770620b4c3472281172a92f0302f8ec6b4c9`。目標112的可丟棄探針開啟 `-options-audit`，在1,253,314,011步取得九段 `GAME.TXT` 同一512-byte DOS 讀取目的緩衝：標題線性 `0x2B0CF`，第1至8列線性 `0x2B0EB`、`0x2B0FF`、`0x2B114`、`0x2B127`、`0x2B135`、`0x2B140`、`0x2B152`、`0x2B168`。各段與固定原始 bytes 相符。原版 `0E2D:1F76` 隨後從線性 `0x2B0CF–0x2B176` 依序讀取168個 bytes，與 `GAME.TXT:0x4CD–0x574` **逐 byte 完全相同**；這一段包含標題、控制行、八列與換行。原版 `0D21:00C6` 在1,253,411,339～1,253,588,150步附近依序讀到不帶 `~` 的標題與八列可見字；但讀字常式的直接 RAM 位址是中間字元緩衝，不是上述檔案讀入目的位址。原版解析緩衝到印字緩衝的**最後搬運邊仍未觀測**，不能把同文並列誤稱完整資料流閉合。

兩次冷啟動收據逐位元組一致；無記憶體監看控制的 `route`、`sources`、`transfers`、全部 `samples`、開檔、鍵盤事件與輸入相同，1,300M 原版索引畫面也相同。[獨立檢查器](../../tools/check_goal112_options_source.py) PASS，[七項正反例](../../tools/test_goal112_options_source.py) PASS，含缺原版 `SKIP 77`、錯 DOS 來源、錯解析讀取、漏印字、壞原版畫面及無監看控制分歧。原版完整收據僅在已忽略的 `workplace/reports/goal112-options/`。

已證實：固定原始位移／bytes、DOS 目的緩衝、原版168-byte逐 byte 讀取、正常玩家開窗、九段印字常式輸出與穩定畫面墨跡。強推論：解析後的九段正是這次視窗印字來源，仍待最後搬運者閉合。未知：反白列、核取圖示、游標及關窗每幀對應的補片相位；適合每欄的中文字級、顏色與快捷鍵視覺呈現；`Tutorial Hints` 圖示是否代表啟用。

### 目標113追加：逐欄印前底圖及可丟棄對照

原版 `0D21:012C` 為實模式 CS:IP；新增預設關閉的 `-options-preprint` 在九欄各自第一次畫布變更**前**擷取整份320×200索引畫布。九次寫入起點依序為1,253,411,390／1,253,433,011／1,253,455,651／1,253,480,309／1,253,501,220／1,253,516,817／1,253,529,697／1,253,550,124／1,253,574,530步。對應印前→1,300M最終畫面的安全區變更畫素數為319／338／349／283／186／172／316／343／246；九個完整寫入差分 bbox（半開）依序為`(67,47)–(147,56)`、`(82,61)–(166,69)`、`(82,73)–(173,82)`、`(82,85)–(155,94)`、`(82,97)–(133,105)`、`(82,109)–(123,118)`、`(82,121)–(158,130)`、`(82,133)–(171,142)`、`(82,145)–(144,154)`。此處的**完整寫入差分**包含非前景色畫素，與上表只量索引68／47的「墨跡 bbox」是兩種不同量測，不互相覆寫。

`preprint-a.json`／`preprint-b.json` 及九張印前畫布逐 byte 相同；`preprint-control.json` 無觀測寫入，正常玩家 `route/sources/transfers/samples/opened/key_events/game_inputs` 與兩次觀測完全相同。三者1,300M原版索引 SHA-256仍為`7093e83e87169f8eb15e733c3d69ec68afd5b78a5d304fa384819c987192a546`，色盤 SHA-256 `b81c99f3ef54dd7015107ece98b6770620b4c3472281172a92f0302f8ec6b4c9`。直接已證實的只有固定畫面相位之九個印前底圖與印後差分；第一列反白與核取圖示的**其他互動相位**仍需另驗。

固定原始 `Cubic_11.ttf` SHA-256 `8de9c249b92bc414cb73f09ddb76c7cb327edb3907b638f0d0bd22691237fd5c`，九筆真 TSV 只在預覽顯示時移除不可見的 `~`，ASCII 熱鍵字母仍留在括號內。貼近原版 A 的逐欄字級為34／25／28／28／25／28／28／27／28px；較可讀 B 為38／28／32／32／28／32／32／31／32px。原文控制與 A／B 使用 Ebitengine 的1280×800畫布，兩種字級皆由[獨立逐像素檢查器](../../tools/verify_card_preview.py) PASS；九安全區外零變更、透明字模恢復當次多色底圖、每欄中文及陰影實際出現。A／B 字級仍只是**視覺候選**，並未由使用者替此視窗定版；它不改正式十七段。

在印字時段針對已知字元緩衝的窄寫入監看記錄為零。這只說明**該時段與地址範圍沒有觀測到寫入**，不能排除較早或經間接位址的搬運；因此原版解析→印字緩衝最後一邊仍為強推論。來源鏈、選取切換、游標與離頁回退任一未閉合，規格都維持 DRAFT。

## 從 DRAFT 到正式覆蓋的閘門

1. 檔案 → DOS 緩衝 → 原版解析／印字緩衝 → `0D21:00C6` → `0D21:012C` 畫布的九欄當次來源鏈，要有雙冷啟動與無監看控制；如讀寫間接，保留原始線性地址及 `CS:IP`，不以命名代替證據。
2. 對未選取列、選取／反白、切換第1與第8列、游標遮字及 ESC 離頁取印前底圖、原文畫素差分與失效負例。要能逐欄清除原文並恢復有紋理底圖，且不覆蓋核取圖示和點擊熱區。
3. 固定真實 TSV 九個來源鍵、譯文及 `~` 快捷鍵對應；逐欄量測中文字模、字級、基線、最長文與安全內距，確定單列溢出與缺字回退策略。需可丟棄視覺對照時先讓使用者評估，再審查 READY。
4. 只有 READY 後才接正式前端。真 Ebitengine 視窗中英同輸入逐幀對照；原版 CPU／RAM／索引／色盤／時間／開檔不變；新畫素只在九個安全區，舊十七欄保持原樣。缺鍵、重複鍵、錯版、缺字模、反白、游標、離頁失敗即逐欄回退。全部通過才限定 CONFORMED，不能把九欄草稿計入正式顯示。

原版輸入與本機索引畫面可能含未取得散布權的素材，只存已忽略的 `workplace/reports/goal112-options/`。本規格及自製驗證器可以推送至私有儲存庫；正式截圖仍須同狀態驗收後才更新。
