## 固定輸入與已證實的原版事件

- 原版 `GAME.TXT` SHA-256 `67a6b5e22d1addc1ae13658d0d7824622f6d21c6c2bfdefc91f9749450cc2e3a`；現行 TSV SHA-256 `c72c862eaecfae51cb9719f255a4c02bcb329bd8e2b969d2c75bad9281055a9c`；固定 `Cubic_11.ttf` SHA-256 `8de9c249b92bc414cb73f09ddb76c7cb327edb3907b638f0d0bd22691237fd5c`；隔離 dosgolem `9dd36726eeaf9c1f3a745aabdcbb84413791d90f`，研究映像 `colonization-research:20260920-r2`。
- **整組印字事件（已證實）**：八列是同一次事件。原版實模式 `0D21:00C6` 以 `SS:BX` 交錯讀 268 次，也就是 134 個字元各接一個零 byte。內容依序為八個「核取前綴 + 空格 + 原文」，前綴 `]` 表示開啟、`[` 表示關閉。開窗時讀取 20-bit 線性 RAM `0x2ADDE/DF`，點擊重印時讀取 `0x2AE46/47`。同一事件內 `0D21:012C` 的改色點數逐列固定為 338／349／283／186／172／316／343／246，另有 344 點落在安全區外，是核取圖示。逐列點擊路徑的 25 次、單列點擊路徑的 4 次與快速點擊路徑的 4 次整組事件，在各種核取與反白組合下全部相同。
- **逐列底圖（已證實）**：各列底圖是在事件進行中、逐列畫上的，開窗前的畫格沒有這些底圖。開窗事件以 1300M 完整畫布與逐點首次寫入前的舊值重建八列印前底圖，和目標113逐列直接擷取的底圖逐 byte 相同。含開窗在內的 16 次穩定事件，底圖只有四種（320×200 半開安全矩形位元組 SHA-256）：
  - 奇數列：一般 `3c24c328cb52d0ddfe5da07f462e685f9d41c89fabad06722a38095ff0078947`，反白 `903ff7549ac31fbb35f8a978ed3072aa4d6c7ab035dcea9ede983aea48490159`
  - 偶數列：一般 `a37541c55677774da71ee04095a82752663fd9e0a24bbaf671d79134a8627bff`，反白 `96f7592f13131bb6eaf8128df7a612867459f9abe14ebedf18d3810405180807`
- **互動（已證實）**：懸停不重印，底層畫布不變，只有 VGA 因游標而暫時不同。點擊一列會觸發三次整組重印：按下、放開，以及放開後約 17 萬步。重印中途可能停頓數萬步，所以分組要以「讀滿 268 次」為界，不能用讀字間隔；前兩次會在下一個畫格之前被下一次重印的底圖覆蓋，只有第三次穩定留存。反白跟著點擊的列走，不跟懸停；核取前綴每點一次就切換。ESC 後八列底層畫布回到開窗前。開窗事件於 1,253,588,893 步結束，下一個 VGA 畫格 1,253,670,000 步時八列真 VGA 與底層相同。
- **重印期間的其他寫入者（已證實）**：按下與放開間隔 0.2M 步的快速點擊路徑（`tools/goal134-quick-click.inputs.json`），三次重印期間的非 `0D21:012C` 寫入全部來自 `0CAE:00A8`：被點列的反白底圖 1870 點，只寫在該列還沒開始印字之前；左側圖示欄 152 點；反白條右端 x=252～253 的 22 點。已印字的列不曾被改動。真 GUI 快速點擊時曾因把這些寫入當成錯誤寫入者而撤銷，原因即在此。
- 雙冷啟動 `row-events` 逐 byte 相同：單列點擊路徑 SHA-256 `19aaeb5bd48cd2d266f0a912aac1c58d542335197c336fd56cca79172356f063`，逐列點擊路徑 `4f4faf594a3ea0dee4b48cccf7e18c7fc5f6d6deb0102a0eeabc628fe30aad5a`，快速點擊路徑 `3141168ae1282aa62044ee4087e281eebacb70ad8be68682bf548a456923306f`。無監看控制的路徑、取樣、開檔、鍵盤事件與輸入一致。`tools/check_goal133_row_events.py` 正例、`tools/test_goal133_row_events.py` 七項篡改負例與缺原版 `SKIP 77` 通過。收據只在忽略的 `workplace/reports/goal133-options-rows/`。
- **仍屬強推論或未知**：`GAME.TXT` DOS 緩衝到高位址 RAM 的完整中間搬運，與規格030相同，屬強推論。鍵盤快捷鍵切換、其他國家或存檔讀入後開窗都未驗證。這些路徑若產生事件，必須通過同一套閘門，否則維持英文。

## 執行期狀態機（設計契約）

1. `idle`：明示旗標、檔案版本、譯文與八個字模都有效時才開始觀測。`0D21:00C6` 第一筆讀取的 `SS:BX` 指向 `0x2ADDE` 或 `0x2AE46`、mode 13h 時，建立**當次**事件權杖，同時撤銷所有舊的逐列權杖。
2. `reading`：依序核對 268 次讀取。核取前綴只接受 `[` 或 `]`，其餘字元必須等於原版列文字。同期間只接受 `0D21:012C` 的改色，以及 `0CAE:00A8` 寫在尚未印字的列、左側圖示欄與反白條右端的底圖；每列在**第一次**被寫入安全矩形時擷取該列印前底圖，底圖必須屬於該列奇偶的兩種已知 SHA。逐列點數到齊才算該列完成。任何錯字、錯位址、錯寫入者、越界或超數，都讓本次權杖失效，八列留英文。
3. `waiting-screen`：事件完成後，逐列等待真 VGA 安全區與底層安全區相同，上限 2,000,000 模擬指令；游標 16×16 矩形壓在該列安全區期間不計入逾時，因為游標疊加會讓真 VGA 暫時不同。底層在等待期間改變，代表被下一次重印取代，該列撤銷。
4. `active`：逐列以「當次印前底圖 + 中文字模」繪製。每幀核對 mode、開檔、底層安全區仍等於印後狀態、真 VGA 與底層相同，以及游標 16×16 矩形不與該列中文前景或陰影相交、滑鼠未按住；不符時該幀該列回英文。底層改變或 ESC 離窗時永久撤銷，只有新的完整事件可以重建。
5. 前端不攔截、不改寫原版輸入，也不寫入原版記憶體。所有撤銷與回英文的原因都記錄在收據。

底圖白名單、2M 上限與游標回退屬本轉譯層的設計；讀字、改色、底圖與重印時序屬固定路徑的已證實事實。
