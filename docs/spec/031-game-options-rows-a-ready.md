## 固定輸入與已證實的原版事件

- 原版 `GAME.TXT` SHA-256 `67a6b5e22d1addc1ae13658d0d7824622f6d21c6c2bfdefc91f9749450cc2e3a`；現行 TSV SHA-256 `c72c862eaecfae51cb9719f255a4c02bcb329bd8e2b969d2c75bad9281055a9c`；固定 `Cubic_11.ttf` SHA-256 `8de9c249b92bc414cb73f09ddb76c7cb327edb3907b638f0d0bd22691237fd5c`；隔離 dosgolem `9dd36726eeaf9c1f3a745aabdcbb84413791d90f`，研究映像 `colonization-research:20260920-r2`。
- **整組印字事件（已證實）**：八列是同一次事件。原版實模式 `0D21:00C6` 以 `SS:BX` 交錯讀 268 次，也就是 134 個字元各接一個零 byte。內容依序為八個「核取前綴 + 空格 + 原文」，前綴 `]` 表示開啟、`[` 表示關閉。開窗時讀取 20-bit 線性 RAM `0x2ADDE/DF`，點擊重印時讀取 `0x2AE46/47`。同一事件內 `0D21:012C` 的改色點數逐列固定為 338／349／283／186／172／316／343／246，另有 344 點落在安全區外，是核取圖示。逐列點擊路徑的 24 次與單列點擊路徑的 4 次整組事件，在各種核取與反白組合下全部相同。
- **逐列底圖（已證實）**：各列底圖是在事件進行中、逐列畫上的，開窗前的畫格沒有這些底圖。開窗事件以 1300M 完整畫布與逐點首次寫入前的舊值重建八列印前底圖，和目標113逐列直接擷取的底圖逐 byte 相同。含開窗在內的 16 次穩定事件，底圖只有四種（320×200 半開安全矩形位元組 SHA-256）：
  - 奇數列：一般 `3c24c328cb52d0ddfe5da07f462e685f9d41c89fabad06722a38095ff0078947`，反白 `903ff7549ac31fbb35f8a978ed3072aa4d6c7ab035dcea9ede983aea48490159`
  - 偶數列：一般 `a37541c55677774da71ee04095a82752663fd9e0a24bbaf671d79134a8627bff`，反白 `96f7592f13131bb6eaf8128df7a612867459f9abe14ebedf18d3810405180807`
- **互動（已證實）**：懸停不重印，底層畫布不變，只有 VGA 因游標而暫時不同。點擊一列會觸發三次整組重印：按下、放開，以及放開後約 17 萬步；前兩次會在下一個畫格之前被下一次重印的底圖覆蓋，只有第三次穩定留存。反白跟著點擊的列走，不跟懸停；核取前綴每點一次就切換。ESC 後八列底層畫布回到開窗前。開窗事件於 1,253,588,893 步結束，下一個 VGA 畫格 1,253,670,000 步時八列真 VGA 與底層相同。
- 雙冷啟動 `row-events` 逐 byte 相同：單列點擊路徑 SHA-256 `19aaeb5bd48cd2d266f0a912aac1c58d542335197c336fd56cca79172356f063`，逐列點擊路徑 `4f4faf594a3ea0dee4b48cccf7e18c7fc5f6d6deb0102a0eeabc628fe30aad5a`。無監看控制的路徑、取樣、開檔、鍵盤事件與輸入一致。`tools/check_goal133_row_events.py` 正例、`tools/test_goal133_row_events.py` 六項篡改負例與缺原版 `SKIP 77` 通過。收據只在忽略的 `workplace/reports/goal133-options-rows/`。

四倍安全矩形第 i 列為 `[320, 236+48(i-1), 1008, 284+48(i-1))`；中文左上角 `(328, 244+48(i-1))`，前景色號 68，陰影色號 47、位移 +4／+4。量測來自 `tools/prepare_goal113_options_preview.py` 的 A 版，收據 SHA-256 `f7046a80bc1bf1f09ac8edd457b7fa8d75062eebfb560f208214dd96a573c8ae`。`tools/verify_card_preview.py` 逐像素 PASS（`e322c32b…`）：九欄以外零差異，透明處回到原版多色印前底圖。每列單行，不換行、不截斷、不縮放；改譯文要重新量測和審查。

## 執行期狀態機（設計契約）

1. `idle`：明示旗標、檔案版本、譯文與八個字模都有效時才開始觀測。`0D21:00C6` 第一筆讀取的 `SS:BX` 指向 `0x2ADDE` 或 `0x2AE46`、mode 13h 時，建立**當次**事件權杖，同時撤銷所有舊的逐列權杖。
2. `reading`：依序核對 268 次讀取。核取前綴只接受 `[` 或 `]`，其餘字元必須等於原版列文字。同期間只接受 `0D21:012C` 的改色；每列在**第一次**被寫入安全矩形時擷取該列印前底圖，底圖必須屬於該列奇偶的兩種已知 SHA。逐列點數到齊才算該列完成。任何錯字、錯位址、錯寫入者、越界或超數，都讓本次權杖失效，八列留英文。
3. `waiting-screen`：事件完成後，逐列等待真 VGA 安全區與底層安全區相同，上限 2,000,000 模擬指令。底層在等待期間改變，代表被下一次重印取代，該列撤銷。
4. `active`：逐列以「當次印前底圖 + 中文字模」繪製。每幀核對 mode、開檔、底層安全區仍等於印後狀態、真 VGA 與底層相同，以及游標 16×16 矩形不與該列中文前景或陰影相交、滑鼠未按住；不符時該幀該列回英文。底層改變或 ESC 離窗時永久撤銷，只有新的完整事件可以重建。
5. 前端不攔截、不改寫原版輸入，也不寫入原版記憶體。所有撤銷與回英文的原因都記錄在收據。

底圖白名單、2M 上限與游標回退屬本轉譯層的設計；讀字、改色、底圖與重印時序屬固定路徑的已證實事實。

## CONFORMED 驗收要求

- 用真玩家輸入重播，中英同輸入對照。至少涵蓋開窗、懸停、點擊一列切換（含反白移動）、ESC 離窗。原版 CPU、完整 RAM、索引、色盤、虛擬時間與開檔逐項相同；中文差分只在八列安全矩形內；標題與既有十九欄不退步。
- 缺譯、重複鍵、缺字模、錯字級、越界、錯底圖、游標遮擋與按住滑鼠的負例都回英文並記錄原因。
- 實際開啟真視窗並以真鍵鼠走到選項視窗、點擊一列，現場截圖與重播逐像素一致，才能宣稱玩家可見完成。原版像素與截圖只留 `workplace/`。
