# 規格045：多層畫面合成效能與 Linux 即時播放驗證

狀態：限定 CONFORMED。入口為[目標184](../goals/184-linux-player-regressions.md)。即時音訊實聽及使用者回報的持續英文仍待確認。

## 已證實的問題

`v.1.0.0-20261005` 私用 Linux `start.sh` 正常操作主選單的50M指令用115.890秒。原版只產生約4.3秒音訊。相同輸入的來源採樣耗時112.522秒；`overlay.Compose`累積CPU占81.27%，`ComposeLayers`占78.95%。來源為dosgolem `b0bf25963ce5a29fb3a3fcf92e211423d4cd4ac8` 的 `overlay/layers.go` 及 `overlay/compositor.go`，採樣器和原始收據見目標184。

`ComposeLayers`每層呼叫`Compose`，即使缺補片、缺字模或停用，也會配置並放大1280×800完整畫面。這是與作品無關的合成成本，不需要修改原版DOS或虛擬時鐘。

本輪滑鼠在主選單`(128,110)`停留後移開，前三列依規格012暫時回退英文，移開後五列均恢復。沒有重現使用者所述的持續英文；不將推測的更新延遲當作已證實根因。

## 合成契約

1. 保留`Compose`、`ComposeLayers`、`Layer`及`Patch`的公開API、來源限制、32層上限、重疊拒絕、逐欄判定順序與回退原因。
2. 每幀驗證來源與色盤並解碼一次。每層先對原始索引畫面驗證，通過後只在互不重疊的安全區恢復底圖及畫字。不得以其他層的中文作為判定輸入。
3. 不修改來源索引、色盤、補片或字模。保留最近鄰縮放與相同色彩換算，優化輸出位元組寫入。
4. 不修改DOS指令、輸入、時鐘、音源或`DrainAudio()`的200k指令邊界。WAV仍取原始合成資料。
5. 先保留舊合成器的隔離副本。以舊版作獨立oracle，比較縮放1～8、多層啟用／停用、缺字、游標改色、安全區邊界及非法輸入；正常玩家GUI與同輸入重播也須相同。
6. 指令前觀測保持每道指令的開檔與模式撤銷判定。只有主選單pending不存在，且CS:IP不是任何既有讀字／入口事件時，可跳過其餘必定無作用的比對。pending存在時仍逐指令檢查來源、返回堆疊與逾時，不延後原有守門。這是已讀現行callback的控制流整理，不新增攔截位址。
7. 前端收到尺寸、跨度與RGBA位元組全等的畫面時，可保留既有texture而不重新上傳。狀態收據仍逐幀更新；任何像素變更都必須標記dirty並正常上傳。
8. 已發布啟動器未覆寫原型`--window-steps`預設100M，會在數秒虛擬時間後自動結束。正式前端預設採uint64上限，正常玩家自行關窗；測試仍明示有限指令數，原版時鐘與關窗收據不變。

## 即時播放與停止線

既有ALSA null不按真實時間讀取，不能證明正常音訊不卡。優化後量測即時供給、缺樣與丟棄，再決定是否需要播放層修正。不得為消除爆音改變原版音高、DOS虛擬時間或無聲取代音樂。尚未驗證的處理不進正式版。

### 播放邊界補充 READY

單次解碼後，相同GUI 50M指令用23.942秒；CPU採樣重播用13.28秒，原始音訊仍約4.3秒。此環境仍可能斷流。既有`audioStream.Read`在缺樣時直接從非零值跳至零，恢復時直接跳回音樂；依原始串流實作確認，這種人工不連續會增加喀聲。授權以下局部修正：

- 只在缺樣與恢復的播放邊界使用5ms線性淡出／淡入，保留原取樣率、音高與原版WAV，不拉長或重寫音樂。
- 缺樣淡出從上一個實際輸出值開始，跨`Read`連續。恢復從當下輸出值漸接新取樣。正常持續供給時原有換算取樣不變。
- 記錄實際缺樣位元組數。以定值非零訊號、短缺樣、跨讀取長缺樣、恢復、左右聲道及積壓丟棄驗證播放邊界的最大跳幅。
- 這項修正只降低播放斷流的喀聲，不宣稱已解決此環境的全部音樂停頓。硬體實聽仍需另外確認。

## READY 審查

現行API與來源、CPU採樣已足夠證實重複解碼瓶頸。上列合成變更只改善輸出方法，沒有新增遊戲語意。授權實作單次解碼與獨立舊版oracle驗證。即時播放變更另依後續量測補充契約，不由此授權猜測調參。

狀態升為READY，2026-10-05。正式合成器限於本專案dosgolem隔離副本，shared dosgolem保持不變；驗證通過後才標CONFORMED。

## 2026-10-05 限定驗證

隔離dosgolem提交`c83740bc5fcb2f2d8f2afb5d57cee6e92bd12f75`的合成器與舊版獨立oracle比較128種輸入，逐欄結果及RGBA全等。25個停用層的20幀測量為舊版3.540秒、新版0.031秒，這是合成器局部量測，不代表整個遊戲快114倍。

正式`v.1.0.1-20261005`的正常Linux GUI 50M指令耗時36.203秒，舊版同類流程115.890秒。有限驗收與不指定上限的正常遊玩均在懸停後恢復五列中文；後者執行110.2M指令再正常關窗。前端Go測試、go vet及缺樣跨讀取／恢復邊界測試通過。主機負載與軟體繪圖會影響時間，本次只證明此環境的改善。實際私用`start.sh`另批正常50M指令為12.208秒，兩批耗時均保留，不外推固定倍率。

正式Linux／Wine以同輸入執行後，完整CPU、1MiB RAM、索引、色盤與原始WAV相同；百科正常輸入重播與舊原文控制側也全等。使用者實際輸入在相同台北時區下，原版狀態、事件及終點PNG與其紀錄全等。兩個移到視窗內空白處的檢查點均為五列中文。收據由目標184索引。

上列合成、既有觀測的早退、相同texture保留、預設執行上限與播放邊界契約升為限定CONFORMED。此聲明不包含即時音樂完全不卡、人耳確認、主選單持續英文的修復，或macOS真機。
