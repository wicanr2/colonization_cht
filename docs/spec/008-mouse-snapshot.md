狀態：CONFORMED<br>

入口：[目標 053](../goals/053-mouse-and-gameplay-route-replan.md)、Issue #25

## 證據與審查

confirmed：隔離 dosgolem 的 `internal/dos/state.go` 只保存位置、按鍵、次數與倍率，
漏掉事件回呼、限制範圍、按下／釋放位置與相對位移。連續冷啟動可點選主選單進入難度畫面，
相同選單快照續跑卻失去回呼。另 `internal/machine/state.go` 沒有保存待執行／執行中的回呼。
本規格從 DRAFT 審查升為 READY：以上均是明確的執行器狀態，不是推測遊戲規則。

## 契約

- DOS 快照升為 v4，保存全部影響滑鼠行為的欄位，診斷紀錄清空；載入也清掉舊機器的紀錄。
- v3 缺少欄位，必須拒絕，不能猜補；歷史實驗使用其原始 commit，新實驗重新冷啟動。
- 本輪只支援沒有待執行／執行中回呼的檔案快照。機器保存及整合保存入口都必須明確拒絕
  不安全邊界，且整合入口在建立／截短輸出檔之前拒絕。載入安全快照時清空原機器的回呼狀態。
- 不改遊戲存檔格式，也不宣稱一般任意時點快照或記憶體內 Snapshot 已全面驗證。
- 單元測試驗證所有行為欄位、診斷紀錄清空、舊版本拒絕與回呼邊界；原版測試比較連續執行、
  選單快照續跑後同一輸入的索引畫面與色盤，均須抵達難度選擇。

實作入口：`workplace/dosgolem/docs/spec/196-mouse-snapshot.md` 與
`internal/dos/state.go`、`internal/machine/state.go`、`internal/state/state.go`。
