## 可重現入口

- [全SS入口組裝器](../../tools/build_hd_full_entry_probe.py)：`--start-step 0`
  包含啟動初段；預設50000000保持原有R49範圍。負值與超過50000000拒絕。
- [背景逐寫組裝器](../../tools/build_hd_background_source_probe.py)：
  `--entry`指定上述步數0輸出，`--reference`指定既有Go模組，
  `--output`指定新的`/out`子目錄。輸出Go、固定前綴檢查點與建置指紋。
  PIK缺失明確回傳77，錯誤版本拒絕；不安裝HD。
- [獨立來源檢查器](../../tools/check_hd_background_sources.py)：
  `--root`指定有`observed/`及`control/`的探針輸出，
  `--decoded`指定R49固定解碼根，`--output`指定新目錄。
  核對完整原版狀態、寫入、每個目的來源格及拒絕的整張比對。
- [來源索引](../../tools/build_hd_source_index.py)可追加
  `--cold-start-entry-report`及`--background-source-report`。
  新證據與既有正式66種素材分開記錄，不增加完成數。

Docker使用既有`hr-go-ebiten:1.26.7-2.9.9-r1`建置與執行，檢查器可用
`colonization-verification:20261007-runtime-r2`。工作樹、原版及dosgolem唯讀掛載，
輸出目錄用UID/GID 1000:1000寫入，預設斷網並設定資源與外層逾時。
本機`commands-r65.json`保留確切命令。

### 輸入、狀態與失敗回退

1. 載入時逐檔核對本節三份原版與兩張生成PNG的指紋、形狀、一般檔案及完整不透明取樣。
   原PNG不裁切、不重編碼。OPENTILE取樣為128×96；OPENMENU取樣為1280×800。
   取樣採像素中心最近鄰，與既有生成素材相同。
2. OPENTILE沿0D46:000A的已驗32×24來源、722位元組編碼、返回位置與768次單次寫入。
   局部來源索引用uint16。只傳播已驗0CBA:009C／009E／00CA複製，核對指令、方向、
   位址與實際來源值。未知寫入包含同值寫入撤銷來源；來源集合超過200000格清空並拒絕。
3. 0D21:012C、16bytes `26882547feca740afecd75dfacb504eb`的原版字形寫入，
   只在舊值等於已驗底紋值時保存底色來源。後續同一寫入必須接續前一字形值。
   其他寫入撤銷底色；一般RAM游標配對依規格066暫存並還原底紋與文字底色。
4. 當11B5:04EE／054A的已驗指令寫到PIK暫存畫布末點時，核對整個64000格指紋，
   保存這一張來源索引。這是來源快取，不保存幀歷史，也不修改原版RAM。
5. 背景繪製須同時通過既有游標／原生畫布守門、模式13h、完整色盤
   243ca37172f22fbfb4182d6d495ad129b9a524f093d67f0d1c5e6d215434ee5f、
   選單矩形兩像素邊框的884格指紋
   2baed3992da35e0710dbaca6b1263f2b4a4e7f52f9e1431120a6ec00de5493c5，
   以及上述UI／當前游標外每個PIK像素。任一不符整張背景回退，沒有局部相似度辨識。
