# 規格033：動態文字抽取與訊息鍵資料模型

狀態：READY（2026-09-26，[Issue #11](https://github.com/wicanr2/colonization_cht/issues/11) 證據審查，見文末）；DRAFT 日期：2026-09-26（[Issue #6](https://github.com/wicanr2/colonization_cht/issues/6)）。本規格把已限定 CONFORMED 的各欄位（規格016～032）歸納成共同資料模型。READY 範圍只含文末表列的輸出類別與欄位；未列者（例如國王接見畫面、`GAME` 下拉選單、`Loading Game...`）仍需各自取證。

## 訊息記錄（文本鍵）

每則可覆蓋的原版文字是一筆記錄，欄位如下；缺任一欄即不得啟用。

| 欄位 | 內容 |
|---|---|
| 文本鍵 | `檔名:0x位移`（單行片段）或 `檔名:@段落`（整頁長文）；模板動態行另帶模板代號 |
| 來源雜湊 | 原始檔 SHA-256、片段 bytes SHA-256、長度；版本不符失敗即關閉 |
| 原文 | 原始檔逐字片段；執行期顯示字串另以當次讀字核對（變數展開後的值或字元序列 SHA） |
| 譯文 | 唯一 UTF-8 TSV（`text/*.zh-Hant.tsv`）的 `zh_hant`，`status=draft` 以上 |
| 輸出情境 | 讀字常式 `0D21:00C6` 的 `SS:BX` 位址型態、改色常式 `0D21:012C`、畫面區域、色號集合、印前底圖條件 |
| 輸出矩形 | 原版墨跡半開 bbox 與四倍安全矩形；中文不得越出 |
| 樣式 | 字型（Cubic 11 固定 SHA）、欄位專屬字級、前景／強調／陰影色號與位移 |
| 缺譯處理 | 保留原版畫面並記錄原因；不得靜默消失 |

## 輸出類別

1. **固定單行**：主選單、難度卡、旗卡、選項各列等。來源鍵為檔案片段；以當次讀字位址、點數、bbox 與印前底圖為權杖（規格012～023、030、031）。
2. **逐字事件列**：每字一次 `0D21:00C6` 事件（字元與 0 交錯、同基址），以整列字元序列 SHA 定鍵。開場字幕、整頁長文（介紹頁、help）、海上選單列屬此類（規格025、026、029、032）。
3. **模板動態行**：一次連續讀取的單行字串，含變數。以位置區域＋模板＋詞典鍵定鍵，變數原值不翻（規格032）。

## 替換單位與回退

- 替換單位是**整則訊息**（或整行模板），不做英文字元對中文字元的替換；原文與譯文長度不等是常態。
- 譯文由固定字型在四倍畫布排版：欄位專屬字級、欄寬內換行（禁則字）、不截斷；超出安全矩形時自動縮字，逐級縮小到欄位字級的 2/3 為止，仍放不下才回原文並記錄（使用者 2026-09-26 決定，見[目標148](../goals/148-font-terms-scope-decisions.md)）。
- 缺譯、重複鍵、來源不符、缺字模或圖集、字元不在圖集中：該則回原文並記錄；原版整體版本不符則拒絕啟動。
- 同文異境：同一英文字串在不同位置出現時，鍵以（類別、文字）決定，位置只作為輸出情境；同一（類別、文字）不得對到兩組鍵。

### 通用行為（皆已由收據驗證）

- **英文原樣模式**：不帶任何欄位旗標，或帶 `--control`（不裝指令觀測、不合成），前端輸出與原版逐像素相同；各目標的英文無監看控制收據即此模式。
- **資料／輸入雜湊檢查**：前端啟動時核對 `OPENING.EXE`、`VICEROY.EXE`、`GAME.TXT`、`LABELS.TXT`、`NAMES.TXT` 的 SHA-256，任一不符即拒絕啟動（`tools/live_menu.go` 的 `versions`）；每筆譯稿列另核對檔案 SHA、位移、片段 SHA、長度；字模與圖集綁定譯稿、字型與（必要時）變數 TSV 雜湊。
- **失敗即關閉**：缺譯、重複鍵、來源不符、字模缺失或綁定不符、字元不在圖集、權杖不符、真 VGA 未同步、游標或按鍵壓住，該則一律顯示原版英文。
- **缺譯日誌**：每幀每欄在輸出 JSON 記錄 `applied` 與 `reason`；海上欄另記 `sea_misses`（字串與次數）；[目標145](../goals/145-coverage-report.md)的報表彙整命中但未建檔的字串。
- **縮字**：新欄位依使用者決定，超界時縮到欄位字級 2/3，仍放不下才回原文（已 CONFORMED 欄位都在原字級內放得下）；執行期拼字引擎已實作並由[目標150](../goals/150-dynamic-overlay-verification.md)驗證。

### 推論等級

- confirmed：上表各類別的讀字、改色、底圖、同步與撤銷行為，都有雙冷啟動與無監看控制收據。
- 強推論：原版檔案到印字緩衝之間的中間搬運（規格016、026、029）；狀態欄 `Gold:`／`Tax:` 與 `LABELS.TXT @CTITLE` 同字（規格032）；西班牙、荷蘭旗卡的檔案到常駐 RAM 搬運（規格022）。這些都不作為顯示鍵的唯一依據：顯示鍵另以當次讀字內容核對。
- 本規格沒有未標示的假說。
