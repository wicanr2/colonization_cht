## 擬定契約

1. 保留規格 009 的版本、入口 bytes、來源 NUL、畫布描述區與 SS/SP 防護。
   對下表逐列建立獨立 pending／patch／字模／缺譯原因；未知事件不翻譯。
   來源雜湊由固定 GAME.TXT 位移取得，並核對 TSV 的來源欄位。
2. 每列完成呼叫後，比對全畫布差異、表列 bbox／點數／色號 254；
   只有正確返回及安全框內差異可建立補片，不由最終截圖猜原底。
3. 每幀以當下原始 indexed／palette 為唯一基底；各列獨立比較完整安全區。
   某列游標遮擋只讓該列回退原文，不能丟棄其他安全的中文列。
   呼叫尚未完成、畫布／來源／描述區變更或另開檔案即撤銷受影響補片。
4. 多列合成仍在隔離 dosgolem 的 overlay 套件：新增只接受互不重疊安全區的
   `Layer`／`ComposeLayers`；每層沿用規格 011 的純函式判斷，輸入不可變。
   對原始畫面獨立求每層結果，再只合併已通過層的安全區；不把上一層中文當原始像素。
   重疊或超過 32 層拒絕，避免不明繪製優先順序；輸出逐層 applied／reason。
   舊 `Compose` 不改契約，保留首列回歸。
5. 預設仍為首列驗收模式；新增明示五列模式與本機字模集合路徑。
   每個字模仍用既有 `fontMask` 格式、candidate_id／譯文 SHA／字型 SHA 綁定；
   不建立第二份譯文，缺檔、缺字、過寬／高或過期只回退該列。
6. 最小驗收：五列清晰畫面、第一至三列游標回退、中文切換、按下重繪、切場撤銷；
   全英文、全部缺字模、單列缺譯、過期／過寬字模控制組，原版狀態須相同。
   五列均須有真實 OnFrame 命中，不能只靠檢查點圖。
   獨立像素驗證須逐列比較：未覆蓋區不變、回退列等於原版、原首列等於已確認原型。
